## Finding

F1 (medium, AC3): another owner's project is refused with the wrong name when its execution repository is
not readable here. `.veldo/control_conversation.py:514` (and `engine/.veldo/control_conversation.py:514`)
calls `project_source` (which raises `missing_evidence:project_repository` at line 134) and then
`trunk_commit` (line 522) before `self._run(ATTACH, ...)` (line 528). The owner and scope checks only run
inside `transition`, during `_run`. So a project owned by someone else, or outside the owner's scope,
whose execution repository is not bound and readable here, or whose HEAD does not resolve, is refused
`missing_evidence:project_repository` and not `missing_authority:project`. AC3 says "anyone else's is
refused by name (missing_authority:project)". It also means the code reads another owner's repository
before it checks authority. I reproduced this with a temporary probe in suite 128 (since restored): a
project `foreign-unbound` (owner `steward`, execution_repository `never-bound-here`) attached by the owner
returned `{'ok': False, 'reason': 'missing_evidence:project_repository'}`. Suite 128's AC3/scope row
does not catch this because its foreign project shares the fixture's readable, bound repository.

What a fix round must change: run the owner and scope checks (the same ones `transition` applies) before
`project_source` and `trunk_commit` in `attach_project`. A closed conversation should also be refused
before either is called. Add a suite 128 AC3/scope check for a foreign project whose repository is not
bound here, expecting `missing_authority:project` with nothing read or cloned.
