# Upgrade to Codex 0.166.0 and Claude Code 2.1.317: the Claude live capture failure

Producer: a Claude implementation agent (not an independent reviewer). Branch
agent/claude/upgrade-codex-0.166-claude-2.1.317, from 91255fda.

## What failed

The lead ran the VELDO-0127 live capture (proof/VELDO-0127/live.py, acct3, claude-haiku-4-5-20251001) on the
binaries qualified at 91255fda. Codex captured. Every Claude run reported "worker did not complete on the
qualified real executable; init set differs; pre-prompt probe evidence missing; execution record first turn
size missing", and the always and deferred pairs reported "context grew with unlisted markers". The init event
listed the plugins veldo-role@inline and cc-plugin-sec-default@builtin. Qualify had turned off four built-in
plugins (agents-md, plugin-authoring, privacy, telemetry) and never named cc-plugin-sec-default.

## Causes

1. Discovery missed the plugin. `claude_builtins` in .veldo/qualify.py read the built-in plugins from one
   init probe in a fresh, empty, logged-out profile. In 2.1.317 each built-in module decides for itself
   whether it loads (`isAvailable`). cc-plugin-sec-default is "seated outermost on a machine with managed
   settings and for Team and Enterprise organizations" (its registration in the binary; the seat is decided
   by `j4()`, whose notes include "not seated: no managed settings and not a Team or Enterprise
   organization"). The empty profile has no organization, so the probe never loads it; acct3's account seats
   it. The binary registers 14 built-in plugins (the registrar that sets builtinPluginsInitialized). The
   probe saw 4.
2. Turning it off cannot work. The module is registered with `enabledFromPolicyOnly`. Its enabled state is
   read from the flag and policy settings and a flag-settings `false` gives way to the policy value
   (`Tn`: `o===!1&&t!==!1?t:o`), so `enabledPlugins: {"cc-plugin-sec-default@builtin": false}` in the
   generated settings would still leave it on. The init comparison (control_agent_config_handoff.difference)
   expected `plugins` to be exactly the role's, so the run stopped with configuration_stop:plugins.
3. The other four messages follow from that stop, not separate faults (established from the code).
   control_engine_claude reads the init event and stops on the difference before the dispatch packet is
   written, so `prompt_written` is false and the probe has no `num_turns` beyond 0 ("pre-prompt probe evidence
   missing"); no turn runs, so no execution record carries a first turn size; evidence.problems then finds
   no integer `first_turn_context` for either run of a pair and reports "context grew with unlisted
   markers" (its check requires both sizes to be integers before it compares them). The capture that
   confirms this on the real account is still open (see Results).

## What changed

- .veldo/qualify.py (and engine/.veldo): `registered_plugins` reads every built-in plugin the binary
  registers from its bytes (the registrar after `builtinPluginsInitialized=!0`, each
  `("<name>",()=>import.meta.require(...)`); a binary where it finds none fails by name. `claude_builtins`
  returns the probe's plugins together with those. `builtin_plugins` splits them by evaluation (AC3): a new
  plugin is listed in `new_capabilities` with its decision from runtime/capability-decisions.json
  (claude_code `plugins`); a granted one goes to the record's `accepted_plugins`, every other one (off, not
  applicable, unevaluated) to `engine_plugins` and is turned off as before. A plugin the replaced record held
  no reading for is new even when the same binary is requalified, so this first run lists the ten the probe
  never saw; a second run rewrites nothing. The output prints the accepted plugins.
- runtime/capability-decisions.json (both copies): the ten plugins. cc-plugin-sec-default granted (the
  organization's security guard, seated by the account and enabled from policy only, so no setting Veldo
  writes turns it off; it adds no tool, skill or policy of its own). Off by VELDO-0127 AC4 (each brings
  context, a skill or a model process the role does not list): claude-platform, claude-test, mods-guide,
  responsive-mode, you-should-know. Not applicable (drawing or tips for the interactive terminal; turned off
  with the rest): diff, easel, mermaid, tips.
- .veldo/control_agent_config_handoff.py (and engine/.veldo): `claude` refuses a record whose
  `accepted_plugins` is malformed or overlaps `engine_plugins`, and puts it in the expected launch set;
  `difference` leaves an accepted built-in plugin out of the plugin comparison, so the run passes whether
  the account seats it or not. Any other plugin is compared as before. A record with no `accepted_plugins`
  gives the same expected set as before.
- Regenerated by qualify: both claude-qualification.json copies, and the four VELDO-0127 resource fixtures
  (they bind the handoff module's digest).
- Suite 126: new row qualify/builtin-plugins. It uses a fake Claude Code whose bytes register three built-in
  plugins while its init probe loads one. It requires that discovery finds all three, that each new one is
  listed with its evaluation (one granted, one unevaluated), that the granted one is accepted and the others
  are turned off, that the init comparison accepts the granted one present or absent, and that an unlisted
  plugin still stops the run. The manifest describes the row.
