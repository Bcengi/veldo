## Finding 1 (high, AC4): setup's own memory check opens each live ChromaDB store in a second process while its store server holds it

- Where: .veldo/control_memory_servers.py:184 (`check(part, 'after')` right after `start` of the store unit),
  .veldo/control_memory_servers.py:228 and :238 (`check(..., 'before')` and `'after'` around the assistant
  rewrite, both run after start_stores, so with both store servers up). The check is VELDO-0182's
  control_memory_check.check, whose probe (.veldo/control_memory_check.py:180-200) runs
  control_memory_adapter.py in the part's interpreter over the part's live data directory: for ava_memory it
  calls `memory_store.get_store()` (.veldo/control_memory_adapter.py:43-44), for memory_kb
  `kb.store._get_client()` (:83-84), each opening the store itself.
- AC4 text: "one store server per store is the only process that opens it", "each store's files held open by
  exactly one process throughout". The setup step breaks that on every first install and every assistant
  rewrite, with the very process AC4 adds to protect the switch. With real chromadb this is a second
  PersistentClient on a store a live server writes (the fixture's own Collection even runs CREATE TABLE on
  open).
- Observed, not inferred: with a temporary probe in the adapter's Mem0.__init__ (restored with git checkout)
  suite 130 stayed green while 6 of 11 probes saw a second pid, the running store server, holding
  mem0_memory's data files at the same moment, for example `1600783 [1600734, 1600783]` (main journey) and
  `1620413 [1620313, 1620413]` (setup row). The before probe at first start (server not yet up) is clean.
- Why the suite misses it: AC4/one-opener samples /proc only during the five writers
  (scripts/suites/130_veldo_0183_memory_servers.py:851), never during the servers step.
- A fix round must: make every check that runs while a store server is up read that store through its server
  (the socket's tools, or the adapter run inside the store server), never by a new opener; or stop the store
  server around such a probe. Then extend the one-opener row (or add one) to sample /proc across the servers
  step, including the after check and the assistant rewrite, with a mutation case that restores the direct
  probe and turns it red.
