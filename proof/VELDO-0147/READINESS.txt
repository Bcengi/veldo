Round 5, 2026-11-27

Why the Codex turn failed in round 4. Not the login: its access credential was
good for days, and the pinned binary has a separate message for a refused login
("workspace routing discovery unauthorized (401)") which did not appear. The
run's Seatbelt profile denies the keychain service (com.apple.SecurityServer and
com.apple.securityd). Codex 0.166.0 takes its root certificates from that
service (http-client/src/native_roots.rs in the binary), so inside the run it
trusted no server and every HTTPS request failed. Measured on the Mac with the
same deny rule: the system root store lists 158 certificates without it and 0
with it; /etc/ssl/cert.pem (128 roots) stays readable. Codex reads that file
when SSL_CERT_FILE names it.

Fix: project_runner_macos_control.engine_environment sets SSL_CERT_FILE to
/etc/ssl/cert.pem for a Codex run on the Mac, unless the operator configured a
value. The keychain stays denied. Claude Code is not given the variable. No
login refresh was built: none was needed, and the Mac still gets no refresh
credential.
