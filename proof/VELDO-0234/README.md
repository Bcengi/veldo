## What changed

- `engine/.veldo/control_factory_setup_api.py` (and its synced `.veldo/` copy): `HTTPS_PORTS = (443, 8443, 10000)`;
  `https_port_option` refuses any other value as `invalid_input:https_port`; `origin_of` / `authority_of` give
  `https://<name>` and `<name>` on 443, `https://<name>:<port>` and `<name>:<port>` otherwise; `serve_state`,
  `transport` and `serve` read and map only the chosen port (`<name>:<port>`, TCP `<port>`, AllowFunnel for that
  key), the occupied refusal names the port; `other_mappings` lists the mappings of other ports, left alone;
  `service_config` and `process_config` take the port (origin, api.origin, api.host), rp_id stays `<name>`;
  `laid_https_port` reads a host's port back from its api-service.json origin.
- `engine/.veldo/control_factory_setup.py` (and `.veldo/` copy): `setup(..., https_port=None)` judges the option
  first, before any other check or write; `--https-port` on the command; a fresh host uses the option (443 by
  default); `rerun_https_port` keeps the laid port, takes the option only on a host without an API configuration,
  and refuses another one as `invalid_input:state_root:holds_https_port` before Tailscale is read or anything
  written; the report's `api` names `https_port`, `origin` and `serve` (`mapping` done or already_done,
  `left_alone` the other mappings found).
- `scripts/suites/support/v171_tailscale.py`: the stand-in takes an HTTPS port and a `neighbors` Serve fragment
  (the edited captured status), accepts `serve --bg --https=<443|8443|10000>` and refuses a port a neighbor holds.
  Default behaviour unchanged (suite 85 44/44).
- New suite `scripts/suites/127_veldo_0234_https_port.py` (registered in manifest.json, requires.json regenerated by
  `run_scope.py --emit-requires`), on VELDO-0171's installed-host fixture as suite 117 reuses it.
- `scripts/check_teeth_mutations.py`: finding 234 (three cases); the anchors of `api171-funnel-in-place-of-serve` and
  `api171-origin-loopback` moved to the new lines with the same defects.
