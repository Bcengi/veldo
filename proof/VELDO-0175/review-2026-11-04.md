## Finding 1 (high): a plain reply whose conversation closes before the PM reads it is never decided, and then blocks all routing

Where: .veldo/control_intake_conversation.py:287 and :358 (read and _reading_plan), with
.veldo/control_workflow_cycle_pm.py:351 (engine/ copies identical).

What happens: a plain Telegram reply is held AWAITING_READING. If the conversation is closed before the PM's
reading runs (the ordinary sequence "great, thanks" then "/close" as replies, since /close is applied at intake
at once; or a close from the API), a reading of `none` reaches _reading_plan, whose _owned_open raises
stale_subject:conversation_closed. read() catches it and returns refused: the record stays AWAITING_READING, no
line is sent to the owner, no turn. The PM cycle picks readings before the inbox (`inbox = ... if not readings`),
so from then on every factory PM cycle re-reads the stuck record and no inbox message, and no new-project message,
is routed again.

Reproduced (suite 131 temporarily extended, restored with git checkout): plain reply to part 1, close, none
reading: `reading False stale_subject:conversation_closed AWAITING_READING`, 0 lines sent to the owner; a second
reading gives the same result.

Criteria failed: AC1 (a closed conversation's reply is refused stale_subject:conversation_closed with one line to
the sender: here no line, and the record never settles) and AC2 (a message no field or reply decides goes to the
factory PM and is routed: every later one is starved while the record exists).

Fix: when the conversation is no longer the owner's open one at reading time, settle the reading as refused for
`none` as read() already does for a command reading: check _owned_open for every reading before _route_plan, set
outcome 'refused' (so _reading_plan retires it READ without a turn) and tell the one refusal line. Add a suite
row: plain reply, close, none reading: one stale_subject line, record READ, a later inbox message routed.
