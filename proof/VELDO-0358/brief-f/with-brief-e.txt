4. Cause (brief E's code, read, not changed): _await_gone registers the worker's pidfd and, when it fires, unregisters
   it ("an exit happens once") but keeps it in `fds`. The next reading, C.retirement, calls containment.alive, which
   reads /proc/PID/stat: a killed worker that is not yet reaped (a zombie: its receiver, its parent, was killed, so it
   is reaped later by its new parent) still has that file, so the reading says not terminated. The loop then polls
   with nothing registered ("not fds" is false), which returns only when the remaining bound has passed. The reap
   that follows sends the service no event. Suite 83 runs the service under the timers profile (every timer at the
   wait hang bound), and brief E puts ORPHAN_SECONDS in the table, so the bound is the hang bound and the pass never
   ends in time. With the production value (5 s) the same path returns 'bound' after 5 s: the release is refused,
   the account slot stays held until release_orphans runs again, and the pass is 5 s late.

5. What would close it, for brief E's owner: after the worker's pidfd has fired the worker has exited, so either take
   the pidfd's own answer as terminated (a zombie is an exited process, whatever /proc still shows), or keep the
   loop from polling when no descriptor is registered. Either makes the wait end on the exit event itself.
