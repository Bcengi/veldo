THE DEFECT
scripts/suites/13_warp_0623_codified_live.py, the WARP-0727 AC1 row, asserted raw set equality
between the entitlement domain (a GIT enumeration, from events.tracked_verdicts) and the validated
corpus (a DISK enumeration, from validate._corpus). An artifact an author has written and not yet
committed is in the second and not the first, so any uncommitted verdict artifact reddened the row
and therefore the whole gate.

The corpus owner already disagreed with the suite in writing. verdict_corpus.divergence() computes
`untracked` as `disk_set - set(direct)` and its docstring says: "the validated artifacts GIT ITSELF
does not report as tracked. Expected and not red: an author validating before committing is the
normal flow." So the suite contradicted the module it tests, and the shape is the one this
repository has been burned by repeatedly: a live-state assertion that reddens on FIRST REAL USE of
the feature it guards.

THE FIX
The comparison now sets aside exactly the owner's own `untracked` bucket and nothing else:

  _v27_untracked = set(_v27_div[_v27_VC.VERDICT_PATTERN]["untracked"])
  _v27_validated_tracked = _v27_validated - _v27_untracked
  _v27_direct, _v27_direct_ok = _v27_VC.tracked_direct(ROOT)
  _v27_untracked_here = _v27_validated - set(_v27_direct)

and the conjuncts became:

  _v27_domain_paths == _v27_validated_tracked
  _v27_domain_paths <= _v27_validated_tracked
  _v27_validated_tracked <= _v27_domain_paths
  _v27_untracked == _v27_untracked_here      <- the forgiven set is pinned to git's own answer
  _v27_untracked <= _v27_validated
  _v27_direct_ok
  not (_v27_untracked & _v27_domain_paths)   <- nothing tracked can be forgiven

WHY THE NARROWING IS NOT A HOLE, verified in the code rather than from the docstring:
`untracked` is `disk_set - set(direct)` where `direct` comes from tracked_direct(), an INDEPENDENT
`git ls-files` read. It is NOT the difference between the two sets under test, so subtracting it
cannot make the equality true by construction. It can only forgive paths git itself says it is not
tracking. The three harmful legs are untouched and still asserted empty for every declared corpus
pattern: entitled_not_validated, contradiction, overclaimed.

The assertion's own sentence was rewritten, because it claimed plain equality and that is now an
overclaim. It states what is set aside, why, and that both harmful directions survive.
