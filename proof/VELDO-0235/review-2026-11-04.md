## Findings

### F1 (VELDO-0234 AC3; the branch's gate): suite 127 rerun/pre-change-host is red at HEAD

`scripts/suites/127_veldo_0234_https_port.py:387-411`. The row lays a host down with the .veldo of the fixed
commit 043c2ef6 and then re-runs setup at HEAD. At HEAD the 0235 engine changes are part of the installed engine,
so the re-run performs VELDO-0189's engine upgrade, and that upgrade appends to its step log
`<home>/state/engine-upgrade.jsonl` (control_factory_setup_upgrade.py:39, 60). `held_files()` excludes bin/, the
service record's engine keys and the SQLite -wal/-shm files, but not the upgrade's own step log. The check at line
411 therefore fails with `[[.../state/engine-upgrade.jsonl]]`.

The row is green at 31923d91 (verified in a clone), which matches proof/VELDO-0234/after-change.txt. It turns red as
soon as 0235 changes an installed engine module. The cause is the row's design, not 0235: because the old commit is
fixed, any later change to the engine closure will redden this row. The proof's own stated exclusion ("the installed
engine, which VELDO-0189's upgrade owns") covers the upgrade's step log in substance.

Fix, within 0234's footprint: either exclude `state/engine-upgrade.jsonl`, or assert that it only gained upgrade
lines. The rest of the AC3 claim (journal head, Serve status, store dump, every other file) stays asserted. Then
re-run 127, and the coordinator on finding 234, at the branch tip.

### F2 (VELDO-0235 AC3): the project view in the UI does not name the destination

AC3 reads: "the project view in the UI and every landing brief ... name the destination in words". The build adds
`destination` and `destinationWords` to ProjectView (`engine/ui/src/features/projects/projects.ts:41-49`), but
nothing renders them. `engine/ui/src/views/ProjectsView.vue` (lines 64 and 79, the card meta and the detail panel)
is unchanged, and no .vue file mentions the destination. The owner cannot see the destination on the screen the AC
names, so AC3 is not met as written.

Resolving it needs a footprint amendment adding `engine/ui/src/views/ProjectsView.vue`, the change proposed in
proof/VELDO-0235/OPEN.md item A, and a UI states proof of it (required_evidence lists ui_states).

There is a secondary point under the same AC. The AC's words are "land and push to <remote>" and "land locally on
<trunk>, nothing pushed". The view's words are "its remote" and "its trunk" (projects.ts:47), because the API does
not serve the remote or trunk name. The amendment should either serve those names or have the owner accept the
generic wording.

## Security checks (no bypass found)

- Destination command: there is no unsigned or non-owner path. OPERATIONS is checked before dispatch, the signature
  is verified before `_owner_problems`, owner equality and version, and no other module writes `landing_destination`.
- Land locally: there is no push. GitLandOps returns through `_publish` (Landing) before the push branch, and its
  constructor refuses land_locally without a wired Landing. The trunk moves only by the update-ref CAS. A forged
  `record_local_publication` effect cannot yield a receipt, because completion re-reads the local ref.
