## Finding

F1 (medium, AC2): "Set at" is the browser's clock, not the credential's set at.
`engine/ui/src/features/servers/CredentialField.vue:45` and `:62` record `setAt: Date.now() / 1000`
when the answer arrives. AC2 requires the form to show "the credential's label, set at and set by",
and VELDO-0144 AC2 defines set at as a field of the `credential` record, written by
`engine/.veldo/control_credential.py:86` and `:90` (`set_at=time.time()` on the authority).

A browser clock reading is a different value. It merely lands close to the record's time when the
browser and the authority share a clock. On the owner's phone, the device the AC names, the browser
clock is independent and can be off by any amount, and the form would show that skewed time as the
credential's set at.

The test hides this: `engine/ui/e2e/servers.spec.ts:302` accepts any time within 5 seconds of the
record. Label and set by are exact, so only set at is affected.

## OPEN.md item A: NOT CONFIRMED as proposed

Does AC2 require the stored time? Yes. It names the credential's set at, and that is the record field
from VELDO-0144 AC2. The time the browser received the API's answer is not that field, so "NOT NEEDED"
does not hold.

Is adding control_api.py to the footprint the correct and smallest fix? Not on its own. Adding
`set_at` to the `keep` list at `engine/.veldo/control_api.py:788` cannot surface a value the authority
never returns: `engine/.veldo/control_credential.py:110` returns only
`outcome, id, reference, version, seq`. The set_at value is created inside the transition (`:86`, `:90`)
and never leaves it.

The smallest correct fix needs both files:
1. `engine/.veldo/control_credential.py`: capture the record's `set_at` (and `set_by`) and return them
   in the result.
2. `engine/.veldo/control_api.py`: add `set_at` (and `set_by`) to `keep`.
3. The synced copies `.veldo/control_credential.py` and `.veldo/control_api.py` (byte-identical today).

Neither file is a protected path. I confirm a footprint addition of exactly
`engine/.veldo/control_credential.py`, `.veldo/control_credential.py`, `engine/.veldo/control_api.py`
and `.veldo/control_api.py` for this purpose, and nothing more. A replayed set
(`control_credential.py:97-102`) must also return the stored record's set_at, not a fresh clock reading.
