## Findings

1. HIGH (blocking): the canonical gate is red. Suite 113's host-scope/own-scope row
   (scripts/suites/113_veldo_0220_gate_host.py:284) needs the systemd user bus, which the confined
   unit leg and the confined mutation worker refuse. local_checks.json records this as 3 of 4 under
   gate_candidate.py, with "Failed to connect to bus: Operation not permitted". The host220-no-scope
   baseline will also be red in a confined worker. The fix is an entry in scripts/gate_unconfined.json,
   which is protected and is neither in this spec's footprint nor in its protected_paths.
   - The implementer handled this correctly. They did not touch the file and recorded the open item
     in the spec's implementation record and in PROOF.md:13-17.
   - The proposed entry (`"rows": "userbus"`) follows the existing `"rows": "strace"` convention, so
     it is the right shape.
   - "Green is the only done", so this needs an owner decision before landing: amend the footprint
     and protected_paths, approve the entry, and run the canonical gate green.
2. MEDIUM: a stopped gate releases the lock while its work keeps running.
   - The holder forwards SIGTERM only to its bash child (gate_host.py:367-369). On SIGKILL,
     PR_SET_PDEATHSIG reaches only that child.
   - So a gate that is terminated or killed midway frees the lock while the stage it started (for
     example a mutation stage) keeps running in the scope. That is the overlap this spec exists to
     prevent.
   - The released-on-exit row asserts that this happens: `alive(stage)` at 113_veldo_0220_gate_host.py:271.
   - The pdeathsig line is not falsified: removing it leaves the suite green.
   - A fix round should stop the scope's remaining processes before or when the lock is released
     (for example kill the scope or its cgroup on every catchable exit, and stop the scope when the
     holder dies). It should also change the row to require that no gate process outlives the
     released lock, and register a mutant for that.
3. LOW: the guard that a nested gate counts as inside only when VELDO_GATE_HOST_HOLDER names a
   live gate-holder ancestor (gate_host.py:187) is not tested. My mutant that drops it survives.
   The /proc/locks condition that follows still limits the damage, but the spec's design decision
   that an environment variable alone never counts as inside has no row that checks it. A fix round
   should add a case where a non-holder ancestor's pid is set in the variable and the lock is held
   above it, and assert NOT STARTED.
4. LOW: proof/VELDO-0220/README.md and OPEN.md are missing. The open decision exists only in the
   spec's implementation record and in PROOF.md. A fix round should add OPEN.md with the
   gate_unconfined.json decision.
