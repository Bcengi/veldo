## Findings

1. HIGH. AC4 is not met and cannot be met as built. Two causes.
   - Exclusive manager claims force serialization. The graph declares both unconfined legs and the
     mutation stage as exclusive manager claimants (scripts/gate_graph.json:19,31,67). The ledger
     therefore serializes those three nodes. Their measured baseline alone is 5,207 + 892 + 834 =
     6,933 s, which is over the 6,000 s bound.
   - The landing run is always cold. Measurements are keyed on the scheduler's and gate_legs.py's
     own source (scripts/gate_schedule.py:323). A node with no measurement reserves the full gate
     capacity (scripts/gate_schedule.py:343). AC4's force-fresh run at the landing candidate is
     therefore cold by construction and runs serially, at roughly the 10,719 s baseline.

   The canonical run and the serialized canonical falsifier were not run (OPEN.md). A fix round
   needs an owner decision recorded as an approved spec revision, not as proof prose. Either:
   - change AC4, for example by moving the bound behind VELDO-0221 or stating the cold-first-run
     cost; or
   - change the design: seed cold claims from an authority measurement, and give mutation a shared
     aggregate claim with per-case exclusive holds over the inherited channel.

   After that, run the canonical qualification.

2. MEDIUM. same-verdicts does not compare against today's serial gate
   (scripts/suites/114_veldo_0216_concurrent_stages.py:173).
   - Both sides of the comparison are the new scheduler: its serial fixture control against
     concurrent mode. AC2 promises parity with "a serial run of the same tree", meaning today's path.
   - A defect shared by both scheduler modes would pass the row. Examples: the new split
     `--leg confined|unconfined` path in gate_legs.run_stage, or the prior-times budget handoff.
   - Fix: add the no-graph serial path (run_stage with leg=None, the verify.sh fallback) as the
     reference side of the comparison.

3. LOW. A refused graph or a scheduler exception leaves no record (scripts/verify.sh:226).
   - The gate exits 1 before it writes a red stamp or a gate.failed event.
   - A capacity or scope refusal raised after read_graph takes the same exit.
   - The console says RED, but a stale stamp from an earlier run of the same tree survives.
   - Fix: write the red stamp and event, or state in the spec that early refusals are unrecorded.

   - When the tree changes, every overlapping node, and then every node, gets the same error.
